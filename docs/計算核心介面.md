# 計算核心介面 v1

本模組是已核准新風率及SF的可執行計算基礎。它整合明確提供的逐時分項，並未生成公司工況、使用排程、完整日射／傳熱模型；不等效 Carrier HAP，不代表正式工程設計已完成。

## 執行與資料流

純 Python 標準庫：`from hvac_engine import calculate_project, InputError`；`calculate_project(payload: dict) -> dict`，不讀設定檔、不修改輸入、不存檔。

命令：`python -m hvac_engine examples/explicit_hourly_input.json --output data/local/synthetic_result.json`。輸出目錄須已存在。輸入錯誤回傳退出碼2，不輸出部分計算結果。此範例完全為合成測試，不是實際項目或公司工況。

## 逐時計算契約

- 頂層：`schema_version: 1`、`time_keys`、非空`rooms`。可加`project_id`、`source_classification`、`notice`，輸出保留其自述來源分類，但不代表已驗證來源。時間為嚴格`YYYY-MM-DDTHH:00`，每個設計日完整00–23時，依時間排序且不重複。可包含多個月份的設計日。
- 每房間：唯一`room_id`、`system_id`、與頂層完全相等的`time_keys`、`has_sf: false`、`needs_fresh_air`明確布林、`people`、`volume_m3`、`exhaust_ach`。無新風需求仍須明確填人數；零人數與缺資料不同。
- `components`為非空分項列表：唯一`name`、與時間同長度的`sensible_kw`與`latent_kw`。零負荷亦明示0；所有負荷數值有限且非負。預先計算的分項可附來源欄位，輸出保留。使用者須保證分項不重複、不遺漏及未含SF；本模組無法從數字判斷隱藏的歷史裕量。
- 新風=需要新風時人數×10L/s，否則明確0；排風=體積×ACH（m³/h），不額外加裕量。不自行推斷用途與ACH，不將人均新風直接視為已完成壓差／轉移風平衡。
- 房間逐時分項先相加；系統按同一時刻相加後取全熱最大值。相同最大值取最早時刻。沒有固定15時或0.85同時係數。
- 輸出`rooms`和`systems`均含`raw_hourly`、`raw_peak`、`sizing_peak`；每筆含時間、顯熱、潛熱、全熱及`has_sf`。`sizing_peak`只將未加裕量峰值乘1.15一次。同時保留`raw_sensible_peak`、`sizing_sensible_peak_kw`供另時刻顯熱能力校核。房間選型與系統選型為獨立視圖；系統永遠從未加SF分項彙總，不能把房間`sizing_peak`再次相加放大。

## 可選表面與濕空氣模組

- `internal_gains(payload,time_keys)`或房間`internal_gains`：明示`name/time_keys/people/person_sensible_w/person_latent_w/lighting_w/equipment_sensible_w/equipment_latent_w`及逐時`people_schedule/lighting_schedule/equipment_schedule`，排程0..1。逐時按人數×人均散熱×排程加照明／設備熱源，再W轉kW。內熱源是顯式熱增益分項，尚未計輻射蓄熱／延遲；不把它稱作完整空間動態冷負荷。`components`可為空列表，但加入surface／internal後仍無分項則拒算；避免同一內熱源重複輸入。
- `surface_load(surface,time_keys)`或房間`surfaces`：`name`、`boundary`（external／adjacent_conditioned／adjacent_unconditioned）、完整`time_keys`、`area_m2`、`u_w_m2k`、逐時`delta_t_k`，以及明示`solar:null`或日射物件。傳熱為UAΔT/1000，ΔT可由已審核方法提供。無法辨識外牆或缺資料時拒算，不能把它默認成零。
- 日射物件：明確`orientation`、逐時`irradiance_w_m2`與`effective_coefficients`，計算面積×輻照×有效係數/1000；係數已包含哪些遮陽／負荷轉換效果由輸入來源記錄。不得重複把同一表面的負荷同時輸入components。此版本不計負向冷負荷／熱損失；遇負值先停止，不靜默截零。
- `moist_air_state(db_c,rh_fraction,pressure_pa)`：0–50°C液態水Buck飽和蒸氣壓近似，RH=0..1，氣壓Pa必填；輸出含濕量kg/kg乾空氣、焓kJ/kg乾空氣、比容m³/kg乾空氣。它是基本近似，尚未與已核准濕空氣圖／標準庫全面驗證。
- `calculate_pau(inlet,outlet,airflow_ls)`：進出口均傳以上三個明確狀態值；風量為入口實際體積流量。按入口比容求乾空氣質量流量，再以進出焓差算冷量；顯熱按入口含濕量熱容量算，餘下為潛熱。僅支援同氣壓冷卻／除濕，不含加熱、加濕或風機熱。零風量是明確0，缺失不是0。結果未含SF；與房間的新風負荷分工由上層明確處理，不自動相減或相加。
- `cfm_to_ls(cfm)`採1ft³=0.028316846592m³的單位換算；`apply_safety_factor(load)`只接收`has_sf:false`及顯潛熱，返回`has_sf:true`，重複套用拒絕。

## 設備候選比較

`select_equipment(requirement,candidates)`：需求必填`equipment_type/airflow_ls/esp_pa/conditions/conditions_reference`；冷量設備另填`total_kw/sensible_kw/has_sf:true`，風機填`has_sf:false`，不對風量／靜壓加冷負荷裕量。候選必填相同`equipment_type`、`model`、相關性能數值、`conditions`與非空`performance_source`。輸入數值代表**同一運行點**，不能把不同風速／工況的最佳數字拼在一起。條件名稱與值必須相等；本模組不插值、不假造工況修正。

只支援以下設備類型及精確工況欄位，所有值必須為有限數值；漏欄、未知欄、巢狀物件或類型不符均返回`NeedsReview`，不提供預設值：

| equipment_type | conditions必要欄位與單位 | 限制 |
|---|---|---|
| chilled_water_fcu | entering_air_db_c、entering_air_wb_c、entering_water_c、leaving_water_c（全部°C） | WB≤DB；0<進水<出水<100°C，僅液態水冷卻，不涵蓋鹽水／加熱 |
| dx_unit | indoor_db_c、indoor_wb_c、outdoor_db_c（全部°C） | 室內WB≤DB |
| fan | air_temperature_c（°C）、air_density_kg_m3（kg/m³） | 0<密度≤10kg/m³；密度來源／工況由conditions_reference記錄 |

溫度欄統一限制-50..100°C。以上是計算介面可支援範圍及基本一致性檢查，並非公司核准設計值，也不是設備實際工作範圍；實際型錄仍須覆核。沒有`equipment_type`亦不能以任意相同字典通過篩選。

缺數據、工況不符或性能不足返回`NeedsReview`及原因；符合返回`CandidatesAvailable`和`eligible`候選列表，不自動發明型號、不指定最低價或任意並聯台數。候選通過亦不代表工程師已核准。

表面與內熱源輸出保留完整`input_basis`深複本，包括來源、面積、U值、溫差、日射與排程；變更輸出不會改動原始輸入。兩者如明示`has_sf`則只接受`false`，`true/null/1`均拒絕；省略時沿用房間未加SF契約。頂層必須為JSON物件；`surfaces`如有提供必須是列表，`null`不能代表「沒有表面」。以上錯誤以`InputError`及CLI退出碼2返回，不掩蓋其他程式錯誤。

## 驗證與限制

`python -m unittest discover -s tests -p test_core.py -v`驗證錯峰系統彙總、多月份時間對齊、缺值與零、NaN／負值、SF重複、新排風、PAU、CFM及設備條件。合成測試只證明這些代數與防誤用行為，不證明與慕拉士實際報表一致；下一步須以對齊後的真實輸入逐項核算。

方法參考：[ASHRAE Fundamentals 濕空氣學章](https://handbook.ashrae.org/Handbooks/F21/SI/F21_Ch01/F21_Ch01_si.aspx)說明以每kg乾空氣為基準的含濕量、焓與比容；[PsychroLib官方API](https://psychrometrics.github.io/psychrolib/api_docs.html)提供基於ASHRAE公式的獨立比對途徑。此版本未安裝／呼叫PsychroLib，亦未完成對該庫的全範圍比對。[Buck原始研究](https://journals.ametsoc.org/view/journals/apme/20/12/1520-0450_1981_020_1527_nefcvp_2_0_co_2.xml)為飽和蒸氣壓近似的研究背景；核心採常用Buck液態水形式，未含enhancement factor，不把近似當高精度實際濕空氣物性庫。工程驗證仍需確認所用形式與氣壓範圍的誤差。
