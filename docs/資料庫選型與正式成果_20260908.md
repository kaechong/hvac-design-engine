# 資料庫選型與正式成果

本輪沿用零售工程輸入，以唯讀 Retool PostgreSQL resource 取得設備主檔、規格、認證與來源文件。2026-09-08 快照包含 452 型號、656 規格、1,613 認證及 49 文件；原始快照保留於本機 `data/local`，Git 保存接入流程及覆核後的補充證據。

## 原始資料覆核

關聯 Hitachi 送審文件第 14 頁的完整室外機名稱為 RAS-3.0HNBRKQ 等，與庫內 RAS-4HNRQ 等名稱不一致；原始規格頁未證實庫內 RPI／RCI 名稱。設計端保存品質發現並排除未證實型號，不回寫資料庫。補充候選來自同一文件內原廠 RPK／RAS 規格頁，標稱性能與本工程設計點性能分開。

現有大型 PAU 及排煙風機不適合直接套用本工程。小風量排風追查 Systemair K 125 EC sileo 原廠同一工作點；新風除濕追查 Geniox 模組化系列，需依盤管與再熱要求取得原廠選型。不得利用不相同轉速的最大風量／最大靜壓或不同工況的冷量湊足需求。

## 重建

使用安裝有文件所需套件的 Python 執行：

```text
python scripts/rebuild_selected_outputs.py
python scripts/rebuild_selected_outputs.py --snapshot data/local/equipment_snapshot_20260908.json
python -m unittest discover -s tests -p test_air_treatment.py -v
```

第一個指令先嘗試即時唯讀查詢；失敗時明示既有快照路徑、原查詢日期及來源。第二個指令明確重用指定快照。回退不修改快照的 `source` 或 `queried_at`。`HVAC_NODE` 可指定 Node，`--output-dir` 可指定成果資料夾。需既有零售輸入、計算結果、本機 FOP 母本與 Retool MCP client。

交付只包含設計說明 DOCX、設計計算表 XLSX 及設備明細表 XLSX。正式報告移除流程／測試文案，固定章原文不改；來源、假設、性能缺項及快照使用狀態集中於內部覆核頁。

## 計算驗收

新風盤管依入口實際風量計算乾空氣質量流量；盤管離風與再熱送風的含濕量相同，盤管冷量減再熱量等於室外至中性送風的淨負荷。房間負荷與新風盤管負荷分開，SF 只加一次。測試覆蓋濕球逆算、無效工況、質能平衡、風量比例及重複 SF 拒絕。

## 本輪成果與驗證紀錄

初選採11台壁掛室內機、3台室外機、2台衛生間排風機及1台新風處理機組。Hitachi RPK-2.5HNBUSQ／RPK-0.8HNBUSQ 配 RAS-3.0HNBRKQ／RAS-7.0HNBRMQ 仍屬有條件候選；Systemair K 125 EC sileo 須重選本工程工作點，Geniox 是系列候選而非已完成的定製型號。詳細政策見「設備選型指引.md」。

末端設計需求38.8302kW，新風盘管原始51.8305kW、含SF59.6051kW、再熱9.1339kW。兩類冷量不重複，再熱不當作另一份冷負荷。

45項測試通過；實際成果檢查175個公式快取、6筆系統需求及13筆機组配置，涵蓋風量換算、SF、負荷密度、型號來源及跨文件對映。Word經本機Word排版並覆核6頁；Excel各工作表經artifact-tool重算與視覺檢查，另唯讀核查匯出檔公式快取、單位及OOXML列印範圍。未完成Microsoft Excel原生應用程式重算／實際列印驗證，不以artifact-tool代替該項證據。
